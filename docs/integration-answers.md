# Ответы OpenCart-разработчику — OneCatalog Import

Решения по вопросам из [integration-plan.md](integration-plan.md) — фиксируем ДО кода.
Платформа: **OpenCart 3.0.3.x**, стандарт **v1.2**. Легенда: 🟢 решено · 🟡 решено с
оговоркой/подтвердить у владельца магазина.

---

## Ответы на вопросы

### 1. Хранение `public_id` 🟢
Своя таблица **`oc_onecatalog_map`** (`product_id` UNIQUE, `public_id` UNIQUE, INDEX по
обоим). Идемпотентность — по ней (не по `model`/`sku`/`mpn`). Причина: у товара
OpenCart нет штатных custom-полей; `mpn` семантически — артикул/партномер, занимать его
служебным ключом нельзя (§5.2). `public_id` редактируется через колонку в списке товаров.

### 2. Характеристики → атрибуты 🟢
OpenCart-атрибут = `attribute_group` + `attribute`, значение в `product_attribute.text`
(свободный текст на язык). Справочника термов (как enum в Bitrix / термы в WC) нет —
это **проще**: find-or-create группы и атрибута **по имени** (регистронезависимо, §5.1),
значение пишем текстом. boolean → «Да»/«Нет» (локализованный текст, false по умолчанию,
§5.6). numeric → текст значения. Группа атрибутов по умолчанию — одна, «OneCatalog»
(или выбор существующей в настройках).

### 3. Категории 🟢
Дерево через `category` + `category_path` (закрытие пути) + `category_description` на
язык. find-or-create по имени в рамках родителя. SEO-keyword (`seo_url`) — **только при
создании**, не затираем при апдейте (§5.6).

### 4. Бренд → manufacturer 🟢
Нативный `manufacturer` (одно имя, без языковых вариантов — это ок). find-or-create по
имени. Лого/доп-поля бренда → событие `brand_imported` (сайтовый слой, §8). По умолчанию
импорт бренда **выкл** (§7), цель — manufacturer.

### 5. Единицы габаритов 🟡 подтвердить у владельца
Маппим на **существующие** классы магазина: вес г → `weight_class` (kg/g…), размеры мм →
`length_class` (cm/mm/in). Конвертируем значение в единицу класса по умолчанию магазина
(универсальный Units, §5.6). Свой класс НЕ создаём (нативное прежде своего). Подтвердить:
какие классы заданы как дефолтные в целевом магазине.

### 6. Очередь 🟡 подтвердить
По умолчанию — **браузерный AJAX-степпер** (не зависит от cron). Если на магазине настроен
cron — добавим cron-контроллер как опцию. Шаг импорта ≥ 10 (§6).

### 7. Промо B2B 🟡
Рекомендация: промо-цена → **`product_special`** (запись со спец-ценой; даты опц.),
базовая → `product.price`. Альтернатива (если витрина так не умеет) — писать в `price`.
Финал — по витрине целевого магазина. (Чистая цена каталога импортом не задаётся, §5.6;
это только §13.)

### 8. Мультисклад 🟡
OpenCart core — **один склад**: остаток по складам фида **суммируем** в `product.quantity`
(дробные → округление по настройке магазина/целое). Раскладка по складам (если стоит
мультисклад-модуль) — через событие `pricestock_updated` (сырые офферы, §13.7).

### 9. Версия / механизм 🟢
Строго **3.0.3.x**; модификации — **OCMOD** (`install.xml`), не vQmod. 4.0.x — отдельная
будущая цель (другая архитектура).

### 10. Языки 🟡
Исходные строки — **en-gb**; перевод — **ru-ru** (§9). `lang` OneCatalog → `language_id`
магазина по карте кодов (en→en-gb, ru→ru-ru…); язык по умолчанию — настройкой. Контент
товара (название/описание/атрибуты) пишем в выбранный language_id; мультиязычный импорт
(один объект + переводы) — общий бэклог стандарта.

## Блокеры (🚫) — решения
- **Нет product-custom-fields** → все служебные данные в своих таблицах
  (`oc_onecatalog_map`, `oc_onecatalog_meta`, `oc_onecatalog_media`, очередь/лог). Это и
  есть реализация инварианта §5.1 «служебное вне формы товара».
- **Атрибуты без справочника термов** → принимаем как есть (текст на язык); строгий
  ручной маппинг «характеристика → атрибут» (как в WC/Bitrix) — опционально, позже.
- **Мультисклад/мультицена по регионам не нативны** → ядро суммирует/выбирает по
  стратегии, проектная раскладка — через события.

## Что подтвердить у владельца целевого магазина (перед стартом)
- Версия OpenCart = 3.0.3.x; доступ к админке (права на установку OCMOD).
- Дефолтные классы веса/длины; язык(и) магазина и language_id.
- Настроен ли cron (для авто-синка §13 по расписанию).
- Есть ли мультисклад-модуль (иначе остаток суммируется в один `quantity`).
